# AI 开始“打草稿”了：推理模型与 Test-Time Compute 的内核

> 2026 年是公认的“智能体爆发年”，而它的地基是**推理模型**：Claude Opus 4.x 的 Adaptive Thinking、GPT-5.6 的思考模式、DeepSeek-R1 的开源路线、Kimi K3、Qwen3.8 的思考/非思考双模式——所有主流模型都在内置“思考”能力。业界甚至预言：到 2026 年底，“推理模型”这个词会消失，因为所有模型都默认会推理。
>
> 但“会思考”不是魔法。它背后是一个反直觉的内核：**把算力从“训练时”挪到“答题时”**。本文带你拆开这台“思考机器”。

---

## 一、先讲人话：学霸为什么打草稿？

同一个数学难题，学渣直接写答案，错了；学霸先在草稿纸上推演三步、划掉、换思路，最后誊写答案。

2022-2024 年的 GPT 系列是“学渣”：你问什么，它**立刻**答什么——不是它不想思考，而是它的训练方式（预测下一个词）决定了它没有“草稿纸”这个环节。

2024 年 9 月，OpenAI 发布 o1，第一次让模型在给出答案前，先生成一大段**内部思考过程**（官方叫 reasoning tokens，社区俗称 thinking tokens）。2025 年 1 月，DeepSeek-R1 开源了同样的能力，还证明了：**思考能力不是闭源公司的专利，它可以被“教”出来，甚至“蒸馏”进小模型**。到 2026 年，打草稿成了行业标配。

为什么？因为有一类问题——数学、代码、逻辑、长链路规划——直接答就是答不对，多想一会儿就是能答对。就这么简单，又这么颠覆。

## 二、内核一：两条算力曲线，第三条路

传统上，让模型变强只有一条路：**训练时计算**（Train-Time Compute）——堆参数、堆数据、堆 FLOPs。这就是著名的 Scaling Law：模型越大，效果越好。但这条路越来越贵，前沿模型一次预训练要烧掉数亿美元。

推理模型提出了第二条路：**测试时计算**（Test-Time Compute）——训练完了，在**回答问题的那一刻**多花算力，也能变强。

```
训练时计算（传统 Scaling）          测试时计算（推理 Scaling）
─────────────────────────          ─────────────────────────
增大参数/数据/FLOPs                  延长思考 token / 多试几次
   效果 ↑，成本 ↑↑↑                     效果 ↑，成本可控
   “练得越多，越聪明”                  “想得越多，答得越对”
```

两个关键发现支撑了这条路：

- **DeepMind《Scaling LLM Test-Time Compute Optimally》（2024）**：测试时计算存在自己的 Scaling Law，且最优策略不是“均匀多花算力”，而是**自适应分配**——简单题少想，难题多想，比无脑延长思考更有效。
- **更炸裂的结论**：**小模型多思考一会儿，可以追平大模型少思考**。这意味着“更大 = 更强”的公式被打破了——计算资源的竞争，从“谁买得起更多显卡训练”部分转移到了“谁更会分配推理算力”。

其实这个规律早有先例：2021 年 Jones 在棋类游戏研究中就发现，训练算力与推理算力的投入可以近似线性地互相替代。围棋的 AlphaGo 也这么干过——训练时算不动，就靠搜索多算几步。

## 三、内核二：模型是怎么“学会”打草稿的？

这是全文最硬核的部分。**思考不是提示词教出来的，是强化学习（RL）训出来的。**

### 3.1 从 CoT 到 RL：提示语 vs 本能

- **CoT 提示**（“请一步一步思考”）是外挂草稿纸：模型被迫写下推理过程，但这是“装出来的”，模型并没有真的学会校验自己的思路。
- **o1/R1 的 thinking** 是内化草稿纸：训练时用 RL 直接奖励“**答对**”（结果）或“**过程正确**”（步骤），模型在试错中发现：**多写几步推理，得分更高**——于是“长思考”成了它的本能。o1 的技术报告明确说：推理能力源于 RL，而且测试时算得越多，模型在数学、代码等基准上的提升越平稳。

### 3.2 DeepSeek-R1：开源路线图

R1 的论文给出了一个漂亮的“三步走”：

1. **R1-Zero（纯 RL 实验）**：不做任何监督微调，只给规则奖励（答对加分），模型竟然自发涌现出“反思、验证、修正”的长思考行为——证明 RL 是思考能力的充分条件；
2. **R1（冷启动 + RL）**：纯 RL 的思考过程可读性差，先用少量人工整理的高质量 CoT 做冷启动，再用 **GRPO**（组内相对策略优化，比 PPO 省显存）强化；
3. **蒸馏（Distill）**：把 R1 的思考能力蒸馏进 1.5B-70B 的小模型。蒸馏版效果与满血版有差距，但在特定任务上常以小博大。

### 3.3 推理时还能“搜索”

除了让模型自己想，还可以让模型**想多遍**再投票——这是搜索类方法，本质是拿算力换正确率：

```
Self-Consistency（多数投票）          Best-of-N / MCTS（择优）
─────────────────────                ─────────────────────
问题 ──→ 答案 A ╮                    问题 ──→ 方案 1 ─┐
      ──→ 答案 B ──→ 投票选出          ──→ 方案 2 ─┼──→ 过程奖励模型打分
      ──→ 答案 C ╯                     ──→ 方案 3 ─┘    → 取最优
```

其中过程奖励模型（PRM）给“每一步”打分而不是只给最终答案打分，是搜索类方法的关键组件——有点像老师批改“步骤分”，而不是只看结果。

## 四、代价与权衡：没有免费的思考

打草稿是要花钱的。推理模型的代价清清楚楚：

| 维度 | 代价 | 缓解手段 |
|------|------|----------|
| Token 成本 | 思考 token 往往是最终答案的数倍，账单翻几番 | 提示词缓存、思考预算 |
| 时延 | 首字延迟从几百 ms 涨到几秒~几十秒 | 轻量思考模式、并行采样 |
| 算力 | 单次请求 GPU 占用飙升 | 推理框架优化、小模型蒸馏版 |

于是 **“思考预算”（Thinking Budget / Reasoning Effort）成了 2026 年最重要的成本旋钮**：

- OpenAI 的 o 系列提供 reasoning effort 三档（low/medium/high）；
- Claude 的 Adaptive Thinking 会自动判断这道题值不值得多想；
- Qwen3/Qwen3.8 支持“思考/非思考”双模式切换——简单问题秒答，难题再启动思考；
- 缓存命中让重复前缀的成本近乎免费：2026 年 5 月 DeepSeek V4-Pro 降价 75% 后，缓存命中输入单价低至 **0.025 元/百万 token**。

经验法则（R1 论文作者也强调）：**简单知识性问题不需要推理模型**——“法国的首都是什么”打草稿纯属浪费。推理模型是为短问题、深推理设计的：数学、代码、逻辑谜题、多步规划。

## 五、下一步：思考 + 工具 = Agent 的雏形

2026 年推理模型最值得关注的演进，是 **o4-mini 可以在思考过程中调用工具**——边想边搜索、边想边执行代码，然后继续推理。这已经不是“打草稿”，而是“打草稿时还能翻书、做实验”。再往前一步，就是长链路 Agent：思考拆解任务 → 调用工具 → 验证结果 → 修正计划。

这也是为什么上一篇《百万 Token 上下文是怎么炼成的》里讲的 KV Cache / MLA 是地基：**思考 token 也是 token**，想得越多，上下文越长，KV Cache 越吃显存——算力、内存、上下文，三者在推理模型时代被牢牢绑在了一起。

## 六、总结：算力经济学的一次转向

回顾全文，推理模型给行业带来的不是“一种新提示词”，而是**算力分配哲学的改变**：

1. **传统**：练得越多越聪明（训练时 Scaling）——烧钱且撞墙；
2. **现在**：想得越多答得越对（测试时 Scaling）——钱花在刀刃上；
3. **未来**：三条曲线并行——预训练、RL 后训练、推理时分配，谁组合得好谁赢。

“更大”不再自动等于“更强”，“更会分配”才是。这或许是 2026 年 AI 领域最值得记住的一句话：**模型的能力上限，正在从“它知道多少”转向“它愿意想多久”。**
