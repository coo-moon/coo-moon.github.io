## 引子：一条 8 倍的新闻，和一个没变快的 API

2026 年 10 月 1 日，英伟达博客发了一篇不起眼的短文：GPT-6 Astra 的 **Ultrafast** 模式跑在 Blackwell 上，token 生成速度最高可达标准模式的 **8 倍**，已向 OpenAI API 和 ChatGPT Work / Codex 用户开放。

新闻稿很克制，但传播出去就变成了"GPT-6 又快 8 倍"。几天后，不少团队把 EAGLE-3 接进自己的 vLLM 集群，实测单路快 2 倍、并发 16 时只剩 1.6 倍——离 8 倍差了一个数量级。

这不是谁在撒谎。同一套技术，在**不同的工作点**上就是两张脸。而理解这两张脸的分界线，恰好是理解整个 LLM 推理优化的一把钥匙。

## 一、人话版：实习生先猜，主编只审

把大模型解码想象成一家报社写稿：

- **主编**（70B 主模型）水平高，但每写一个字都要把整柜资料重新翻一遍（把全部权重从显存搬到计算单元），慢得离谱；
- **实习生**（1B 草稿模型）水平一般，但翻资料极快，可以先一口气猜出接下来 4 个字；
- 主编拿到这 4 个字，**只翻一次资料**，就能同时判断"这 4 个字我认不认"，顺便再自己补一个字。

```
标准解码：  [主编]→t1   [主编]→t2   [主编]→t3   [主编]→t4     ← 搬 4 次权重
投机解码：  [实习生]→ t1 t2 t3 t4
                          ↓
            [主编] 一次前向：验 4 个 + 送 1 个
            接受 t1 t2 t3 → 这一轮净赚 3 个 token
```

三个关键点，缺一不可：

1. **猜是并行的**，所以猜错也不至于更慢——最差情况退回标准解码，还白得一个 token；
2. **验证是一次前向**，不管验 1 个还是 5 个 token，权重只搬一遍；
3. **猜错不会改变结果**——这是它最反直觉、也最优雅的地方，后面第三节证明。

## 二、为什么"猜"几乎是白赚的：解码的物理瓶颈

要理解投机解码为什么能免费，得先看 decode 阶段到底卡在哪。

自回归解码每生成一个 token，需要把**全部模型权重**从 HBM 读进 SM 一次。以 70B 模型、FP16 为例：

```text
权重体积      = 70e9 × 2 字节        = 140 GB
H100 带宽     = 3.35 TB/s
单步理论耗时  = 140 / 3350 s         ≈ 41.8 ms
单路解码上限  = 1 / 0.0418           ≈ 23.9 token/s
```

而这一 step 实际做了多少计算？`2 × 70e9 = 140 GFLOP`，摊到 41.8ms 上只有 **3.35 TFLOPS**——H100 的 FP16 稠密算力是 989 TFLOPS。**算力利用率 0.3%。**

用 Roofline 的语言说：batch=1 的解码，算术强度只有 `2 FLOP / 字节`；而 H100 的"屋脊点"在 `989e12 / 3.35e12 ≈ 295 FLOP/字节`。两者差了近 100 倍，说明 GPU 绝大部分时间在**等内存**，而不是在算。

这就是投机解码的经济学基础：**它不省计算，它把闲置的算力换成带宽效率。** 一次前向验 γ+1 个 token，权重还是只搬一遍，等于把每次搬运的"有效载荷"放大了 γ+1 倍。计算量涨了 5 倍？无所谓，因为原本 99.7% 的算力在空转。

## 三、无损的魔法：拒绝采样如何保证"猜错也不跑偏"

很多人第一次听到投机解码，直觉是"这不就是让大模型给小模型擦屁股，输出质量肯定要降"。恰恰相反：**在标准实现下，它的输出分布与目标模型严格相同**，不是近似，是数学等价。

机制只有两行：

```python
# 草稿模型 q 给出 x，目标模型给出 p
if random() < min(1, p[x] / q[x]):
    accept(x)                      # 按 min(1, p/q) 接受
else:
    x = sample(normalize(max(0, p - q)))   # 拒绝后从"残差分布"重采样
```

为什么这样能还原 p？把 x 被接受的概率拆开看：

```text
接受路径贡献：  q(x) · min(1, p(x)/q(x)) = min(p(x), q(x))
拒绝路径贡献：  从 max(0, p-q) 归一化后采样，摊回原尺度 = max(0, p(x) - q(x))
两者相加：      min(p,q) + max(0, p-q) = p(x)   ✅
```

如果草稿的分布比目标"薄"（q < p），多出来的概率质量会通过拒绝分支补回来；如果比目标"厚"（q > p），超出的部分会被按比例拒掉。**一进一出，正好抵消。**

这在工程上带来两个直接推论：

- **它和量化、蒸馏、剪枝有本质区别**。后者改的是模型分布，必然损失质量；投机解码改的只是**采样路径**，输出统计特性和原模型一致。
- **KV Cache 必须能回滚**。第 k 个草稿 token 被拒后，k 之后所有位置的 KV 全部作废。PagedAttention 里的做法是截断 block table——这几乎就是数据库里事务 `ROLLBACK` 的翻版：先乐观地写，验证失败就 undo。生产环境里投机解码最常出的 bug，不在算法，而在这块"回收站"没打扫干净。

## 四、加速比公式：α、γ、c 三张牌

Leviathan 等人 2023 年的论文给了一个非常干净的结论。设：

- **α**：草稿 token 被接受的概率（acceptance rate）
- **γ**：每轮猜几个 token（draft length）
- **c**：一次草稿前向 / 一次目标前向 的耗时比

则期望墙钟加速比为：

```text
               1 − α^(γ+1)
speedup = ─────────────────────
          (1 − α) · (γ·c + 1)
```

分子 `(1 − α^(γ+1)) / (1 − α)` 是每轮**期望被接受的 token 数**（含白送的那一个）。分母是这一轮付出的代价：γ 次草稿 + 1 次验证。

这张表（c = 0.05）能说明大部分工程决策：

| α \ γ | 1 | 2 | 4 | 6 | 8 |
|---|---|---|---|---|---|
| 0.5 | 1.43× | 1.59× | 1.61× | 1.53× | 1.43× |
| 0.6 | 1.52× | 1.78× | 1.92× | 1.87× | 1.77× |
| 0.7 | 1.62× | 1.99× | 2.31× | 2.35× | 2.28× |
| 0.8 | 1.71× | 2.22× | 2.80× | 3.04× | 3.09× |
| 0.9 | 1.81× | 2.46× | 3.41× | 4.01× | 4.38× |

三条读法：

1. **α 是命门，天花板是 1/(1−α)。** α=0.8 时无论怎么调参最多 5 倍；α=0.5 时最多 2 倍。所以"提升接受率"永远比"加长草稿"划算。
2. **γ 不是越大越好。** 因为 α^γ 指数衰减，而成本 γc 线性增长。α=0.6 时 γ 超过 4 就开始倒亏——这是新手最常踩的坑：以为猜得越多赚得越多。
3. **c 决定草稿值不值。** 草稿模型若能压到目标模型的 1/20 成本，γ=4、α=0.8 能拿到 2.8 倍；如果草稿本身要 1/3 的成本（c=0.33），同样的 α 只剩 1.4 倍。

## 五、2026 年的四种"草稿"：从外挂到内置

过去两年，这条赛道的竞争焦点从"要不要投机"变成了"**草稿器怎么和主模型共享计算**"。

| 方案 | 草稿来源 | 额外开销 | 典型 α | 适用场景 |
|---|---|---|---|---|
| **n-gram / Prompt Lookup** | 直接从上下文里抄片段 | ≈ 0 | 复制型任务极高 | 代码补全、RAG 摘要、格式改写 |
| **小模型 draft** | 同家族 1B 模型 | 一份模型显存 | 0.5–0.7 | 通用，但运维两套权重 |
| **EAGLE-3 特征头** | 复用主模型各层隐状态，单层 Transformer 头 | 一个 head | 0.80–0.88（代码） | 主流生产方案，vLLM / TensorRT-LLM 内置 |
| **MTP 内置头** | 训练时就多预测一个 token，共享 embedding 与输出头 | 训练期成本 | 0.80–0.90（第 2 个 token） | DeepSeek-V3 起的主流架构选择 |

几个值得记住的实测数字：

- **DeepSeek-V3 的 MTP**：第二个 token 接受率 80%–90%，TPS 提升 **1.8 倍**，且不需要第二套模型权重——把"草稿能力"直接焊进预训练目标里。
- **vLLM 的 EAGLE-3.1**（2026 年 5 月合入主线）：并发 1 时输出吞吐 **2.03×**，并发 4 时 1.71×，并发 16 时 1.66×。注意它和早期方案最大的区别：**增益在高并发下没有完全塌掉**。
- **AWS 的 P-EAGLE**（2026）：把"串行起草 γ 个 token"改成并行起草，比 EAGLE-3 再快 **1.69×**。这说明瓶颈已经从"接受率"转移到了"起草本身的延迟"。

## 六、为什么你的线上只剩 1.1 倍：四个杀手

现在回到开头那个反差。8 倍是厂商在**特定工作点**上的 token 生成速度，不是你的端到端 QPS。

**杀手一：高并发把 Roofline 翻转了。**
batch=1 时你在内存墙左侧，算力白送；batch 涨到几百，权重只读一次却要服务几百条序列，GPU 直接撞上算力墙。此时验证 γ 个 token 不再是"顺手",而是实打实多花 γ 倍 FLOPs——加速比公式里的 c 虽然没变，但"验证"这件事本身从免费变成了昂贵。生产基准的普遍结论是：**低中并发 2–3 倍，高 batch 下趋近 1.0–1.2 倍**。离线批处理任务开投机解码，往往是纯亏。

**杀手二：TTFT 一点没动。**
投机解码只加速 decode。prefill 阶段读 10 万 token 的长上下文，该多久还是多久。在 Agent 场景里，首 token 延迟常常占总时延的一半以上，用户体感提升远小于吞吐数字。

**杀手三：显存和调度被挤占。**
草稿 head、树状验证的多个分支、被拒绝后作废的 KV slot，都要占显存。在 24GB 卡上，这些开销可能逼你把 `max_num_seqs` 调小，吞吐反而下降。

**杀手四：接受率不等于正确率。**
α 衡量的是"草稿像不像主模型",不是"答案对不对"。草稿和主模型可以一起错。2026 年 MLSys 有篇论文标题就很扎心：《Speculative Decoding: Performance or Illusion?》——它系统性地指出，很多报告里的加速比来自有利的 prompt 分布，换个领域就蒸发。同一套配置，代码任务的接受长度能到 5.24，创意写作只有 1.84。

## 七、跳出推理：这是"乐观执行"的第三次重演

如果把视线拉远，投机解码并不新鲜，它是计算机系统里一个反复出现的思想的第三次大规模落地：

| 年代 | 系统 | "猜"的形态 | "验"的形态 |
|---|---|---|---|
| 1970s–90s | CPU 乱序执行 | 分支预测，提前执行 | 提交时校验，失败则回滚寄存器 |
| 1981 | 数据库 OCC | 读不加锁，先干活 | 提交时验证读写集，冲突则 abort |
| 2023–26 | LLM 投机解码 | 小模型/特征头起草 | 主模型一次前向并行验证，拒绝则重采样 |

它们的共同结构是：**把串行依赖链上"不确定"的部分提前并行化，用便宜的验证替代昂贵的等待。**

而它们失效的条件也完全一致——**验证不再便宜的时候**。CPU 的预测失败要冲刷流水线，数据库的冲突率高时 OCC 不如两阶段锁，LLM 在高 batch 下验证要吃满算力。乐观策略永远是一门关于"猜对概率 × 验证成本"的生意，而不是一条免费的捷径。

## 八、给你的四条实践准则

1. **先量 α，再上线。** vLLM 会暴露 `draft_acceptance_rate`。低于 60% 别开，70% 以上才有正收益；掉到 40% 说明草稿模型和你的输入分布不匹配。
2. **按并发分层决策。** c=1–4 的交互式场景（IDE 补全、客服、Agent 单步工具调用）收益最大；离线批量、高并发网关优先考虑 PD 分离和前缀缓存。
3. **优先零成本草稿。** 代码补全、RAG 摘要、格式改写这类"大量复制上下文"的任务，先用 prompt lookup / n-gram，c≈0，常常比训练一个 EAGLE 头更划算。
4. **别只盯 decode。** 长上下文场景下，前缀缓存（KV Cache 命中）和 PD 分离的收益，可能比投机解码高一个数量级。三者是乘法关系，不是替代关系。

## 结语：8 倍不是魔法，是工作点

回到那条新闻。8 倍是真的，但它的完整定语是："在 Blackwell 上、特定 batch 配置下、token 生成速度相比标准模式、最高"。

这句话里的每一个限定词，都对应 Roofline 图上的一个坐标。**工程判断力，本质上就是知道自己的系统站在图上的哪个点。** 站在内存墙左侧，算力是免费的，投机解码是印钞机；站在算力墙右侧，算力是稀缺的，投机解码只是把你的 GPU 时间换了个花法。

同一个算法，两种命运。这不是 AI 时代的新故事，这是计算机体系结构讲了五十年的老故事——**瓶颈在哪里，优化就在哪里；瓶颈变了，优化就该换。**
