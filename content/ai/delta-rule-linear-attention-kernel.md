# 记忆不是往纸上堆：Delta Rule 与线性注意力的「改写」内核

> 2026 年的模型发布清单里，有一个词出现得反常地频繁：**混合注意力**。Qwen3.5 是 3 层 Gated DeltaNet 配 1 层全注意力；Kimi Linear 是 3 层 KDA 配 1 层 MLA；Ling 2.5 更激进，7 层线性配 1 层全注意力。
>
> 八月[那篇长上下文拆解](/posts/million-token-context-hybrid-attention/)回答了「为什么要换掉全注意力」。这篇往下挖一层：换上去的那个东西，**到底是怎么把记忆写进去的**。

## 一、先讲人话：一本不能撕页的笔记本

想象两个人在读同一份一千页的档案。

第一个是**全注意力**：每读一句，就把前面所有页重新翻一遍，逐字比对「这句和之前哪句有关」。记得极准，但读到第五百页时，他每读一句要翻五百页。

第二个是**线性注意力**：手边只有一本固定厚度的笔记本，每读一页就写一行摘要；要回答问题时只翻自己的笔记本，绝不回看原始档案。

第一个人的成本随页数**平方**增长，第二个人是**线性**。但第二个人有个致命问题：**本子写满了怎么办？**

这就是线性注意力几十年反复卡住的地方。而「怎么办」的答案，藏在一个 1960 年就写下的规则里。

## 二、第一性原理：注意力本质上是一张联想表

先看全注意力在算什么。设序列长度 n，头维度 d：

```
        Q Kᵀ            softmax            V
   (n × d)(d × n)  →   (n × n)     ×   (n × d)   →  (n × d)
                        └─ 每个 token 对每个 token 打分 ─┘
```

那个 `n × n` 的分数矩阵就是成本来源：n 翻倍，矩阵大 4 倍。

线性注意力换了个思路：用一个特征映射 φ 代替 softmax，然后利用矩阵乘法的**结合律**把顺序换过来：

```
   先算 (φ(Q) φ(K)ᵀ) V   →  n×n 的中间矩阵，贵
   先算 φ(K)ᵀ V          →  d×d 的中间矩阵，便宜！
```

于是有了一个**固定大小的状态** `S`（d_k × d_v）：

```
   写入：S_t = S_{t-1} + k_t v_tᵀ        ← 每来一个 token，往表里加一条
   查询：o_t = S_t ᵀ q_t                 ← 用 q 去表里查，不回看历史
```

这两行就是线性注意力的全部。算一笔直观的账：如果 d_k = d_v = 128，`S` 是 16384 个浮点数。当上下文是 100 万 token 时，**平均每个 token 只分到 0.016 个数**。

这就是全部张力的来源——你不可能无损地记住一百万条记录，只能记住它们的**统计结构**。

```
全注意力：KV Cache = 每条记录一份      线性注意力：State = 一张固定大小的表
  ┌──┬──┬──┬──┬──┬──┐                  ┌─────────────┐
  │k1│k2│k3│k4│k5│… │  随长度线性增长    │  d×d 矩阵   │  长度无关，常数
  └──┴──┴──┴──┴──┴──┘                  └─────────────┘
      精确可回溯，贵                          有损压缩，便宜
```

## 三、四代更新规则：从「堆」到「改」

上面那行「S = S + k vᵀ」有个致命缺陷：**只加不减**。每来一个 token，状态范数就涨一点，长上下文时旧信息被彻底淹没——文献里叫 attention dilution（注意力稀释）。

怎么修？四代方案，一行比一行精细：

```
第 0 代  Hebbian 累加：   S_t = S_{t-1} + k_t v_tᵀ
第 1 代  Delta 规则：     S_t = (I − β_t k_t k_tᵀ) S_{t-1} + β_t k_t v_tᵀ
第 2 代  门控 Delta：     S_t = α_t (I − β_t k_t k_tᵀ) S_{t-1} + β_t k_t v_tᵀ
第 3 代  KDA：            S_t = (I − β_t k_t k_tᵀ) · Diag(α_t) · S_{t-1} + β_t k_t v_tᵀ
```

### 第 1 代：Delta 规则 = 先读旧值，再写误差

DeltaNet 的洞察是：别把状态更新看成「记录」，看成**在线学习**。

把 `S` 当作一张要被学习的「快速权重」，第 t 步的重建损失是：

```
L(S) = ½ ‖ Sᵀ k_t − v_t ‖²
```

也就是：**用当前的记忆去回答 k_t，答案和真值 v_t 差多少**。对 S 求一步梯度下降（学习率 β_t）：

```
S_t = S_{t-1} − β_t ∇L = (I − β_t k_t k_tᵀ) S_{t-1} + β_t k_t v_tᵀ
```

那个 `(I − β k kᵀ)` 就是**擦除项**：它把状态里与 k 同方向的分量先投影掉，然后把 v 写进去。

举个具体例子。假设 `k = [1, 0]`，记忆里已经存了 `k → 5`，现在来了新的一对 `k → 3`：

| 规则 | 运算 | 结果 |
|---|---|---|
| Hebbian 累加 | 5 + 3 | **8**（错的，越叠越离谱） |
| Delta 规则（β=1） | 5 + (3 − 5) | **3**（正确覆盖） |

Hebbian 是**盲写**（INSERT），Delta 是**读-改-写**（UPDATE）。做过后端的人应该立刻认出这个模式：这就是数据库里 `UPDATE ... WHERE key = ?` 和 `INSERT` 的区别。线性注意力的状态更新，本质是一条带条件的覆盖写。

### 第 2 代：加一个遗忘门

Delta 规则解决了「覆盖」，没解决「过期」。一个一年前的事实，如果没有新值来覆盖它，会永远躺在表里抢注意力。

Gated DeltaNet 引入标量门 `α_t ∈ (0,1)`，每次更新前先把整个状态乘一个衰减：

```
S_t = α_t (I − β k kᵀ) S_{t-1} + β k vᵀ
```

`α_t` 由当前输入动态算出，相当于一个 **TTL / 权重衰减**。这和 Mamba-2 的 SSD 那套「标量衰减」是同一个思想——Gated DeltaNet 那篇论文的标题就写得很直白：《Improving Mamba2 with Delta Rule》，把 Mamba 的衰减和 DeltaNet 的纠错合到了一起。

但 `α_t` 是一个**标量**：整个 head 的所有通道共享同一个遗忘速率。可记忆的内容显然不是铁板一块——有的维度记的是长期事实，有的维度记的是最近几轮对话的语气。

### 第 3 代：KDA 的通道级擦除

Kimi Linear 的 KDA 只改了一个符号，机制上却跨了一大步：把标量 `α_t` 换成**对角矩阵** `Diag(α_t)`。

```
标量门：  S ← α · S              所有通道一起褪色（一刀切）
通道门：  S ← diag(α₁…α_d) · S   每个通道独立决定保留多少（外科手术）
```

再叠上 Delta 的投影擦除，一个 KDA 层就能同时做两件事：**对某个 key 精确改写**（delta），**对整片无关记忆缓慢淡出**（channel-wise gate）。论文里把它称为「更细粒度的容量管理与遗忘策略」。

顺带一个有意思的推论：既然门控本身就提供了「按距离衰减」的归纳偏置，位置编码就不是必需品了。Kimi Linear 干脆在全局注意力层里**去掉了 RoPE（用 NoPE）**，把位置信息交给 KDA 的数据依赖衰减去学。这和当年「必须显式加位置编码」的常识正好相反。

Kimi Linear 论文（arXiv 2510.26692）给出的数字：3B 激活 / 48B 总参数，3:1 的 KDA:MLA 层间混合，KV Cache 占用最多降低 **75%**，1M 上下文下解码吞吐提升最高 **6 倍**，且在同等训练配方下全面超过纯 MLA。

| 代数 | 更新方式 | 能否遗忘 | 遗忘粒度 | 代表 |
|---|---|---|---|---|
| 0 | 外积累加 | ❌ | — | Linear Transformer (2020) |
| 1 | Delta 纠错 | ❌ | 按 key 方向 | DeltaNet (2024) |
| 2 | 门控 + Delta | ✅ | 每 head 一个标量 | Gated DeltaNet / Mamba-2 |
| 3 | 通道门控 + Delta | ✅ | 每个特征通道 | KDA / RWKV-7 |

> RWKV-7 走的是同一条路：把 Delta 规则推广成「对角 + 秩一」的转移矩阵，用向量值的数据依赖衰减。三条独立的技术路线（Kimi、Qwen、RWKV）在 2025-2026 年收敛到同一个结构，这通常说明它接近了某种局部最优。

## 四、为什么「擦」比「堆」重要：固定记忆的碰撞问题

一个 128×128 的状态装 100 万 token，直觉上必然崩。但真正的问题不是「装不下」，而是**串扰（interference）**。

`S = Σ k_j v_jᵀ` 是一个叠加态。如果所有 key 两两正交，它们可以互不干扰地共存——这就像哈希表里每个 key 落在不同的桶。但真实文本的 key 高度相关：「苹果」和「苹果公司」的表示几乎同向，写第二个的时候会把第一个的读出污染掉。

Delta 规则在这里的作用，等价于**哈希表插入前的探测**：先算出这个 key 位置上已经有什么（`Sᵀk`），把冲突的那部分扣掉，再写入新值。它不是让表变大，而是让**每次写入尽量不破坏已有条目**。

当然，擦除也有代价。如果同一个 key 在不同语境下对应多个值（比如「他」指代了两个人），Delta 的覆盖语义会丢掉其中一个。这正是纯线性注意力的软肋：**它擅长记住「趋势」，不擅长精确召回「某一条」**。

于是就有了 2026 年的标准答案——不是二选一，而是分工：

```
┌──────────────┬──────────────┬──────────────┬──────────────┐
│  KDA 层      │  KDA 层      │  KDA 层      │  全注意力层  │
│  流式记忆     │  流式记忆     │  流式记忆     │  精确检索     │
│  O(1) 状态    │  O(1) 状态    │  O(1) 状态    │  O(n) KV     │
└──────────────┴──────────────┴──────────────┴──────────────┘
       3 层便宜                   + 1 层昂贵（但补齐了复制/检索能力）
```

3:1 不是拍脑袋的折中，而是**承认线性层有结构性缺陷后的一次工程妥协**：让 3/4 的层去扛长上下文的成本，留 1/4 的层专门做「回到原文找那一句」。Qwen3-Next 和 Kimi Linear 独立收敛到同一比例，Ling 2.5 甚至推到 7:1——比例是调出来的，但「少数全注意力层保底」这个结构是必然的。

## 五、工程视角：这个公式凭什么能跑在 GPU 上

理论上优雅的递推，工程上曾经是灾难。因为 `S_t` 依赖 `S_{t-1}`，一万个 token 就是一万次串行的小矩阵运算——GPU 最怕这个：算力闲着，全在等 kernel launch 和显存读写。

2024 年 DeltaNet 那篇论文的贡献，是把这个串行递推**变成矩阵乘法**，靠的是两件数值线性代数里的老工具：

1. **分块（chunkwise）**：把序列切成 C=64 或 128 的块。块内用小规模注意力精确算，块间只传一次状态。
2. **WY 表示**：一串 Householder 变换的乘积 `(I−β₁k₁k₁ᵀ)(I−β₂k₂k₂ᵀ)…` 可以压缩成 `I + W Yᵀ` 的低秩形式，不必逐步物化 d×d 矩阵。

代价变成：每块求一个 C×C 的下三角矩阵逆（C 很小、可并行），其余全是稠密 matmul。于是训练从「O(n) 次串行小算子」变成「O(n/C) 次大矩阵乘」，正好喂饱 Tensor Core。

这也解释了为什么线性注意力在 2020 年提出、2024 年才真正可用：**卡的不是数学，是 kernel**。

另一个容易被忽略的工程后果在推理侧：状态**不可任意回退**。传统的 KV Cache 可以按 token 精确前缀匹配（radix cache），但线性层的状态是一路摞出来的，要回到某个中间位置，只能回到**保存过检查点的块边界**。所以混合架构的推理引擎，缓存管理粒度从 token 变成了 chunk——这也是为什么 KDA 的 kernel 必须和 vLLM/SGLang 深度绑定，不能只当个算子替换。

还有一个反直觉的权衡：**线性注意力不是在所有长度都更快**。短上下文时，全注意力只需读几百个 KV，而线性层每个 token 都要把整个 d×d 状态读写一遍，访存量反而更大。混合模型的收益曲线是「短上下文略亏、长上下文大赚」——这解释了为什么它先出现在长上下文和 Agent 场景，而不是聊天机器人。

## 六、总结：记忆的价值在于「改写」

回头看这四代公式，真正的分水岭只有一个：**记忆是只能追加，还是可以被修正**。

- Hebbian 累加像往墙上贴便签，越贴越厚，最后什么都看不清；
- Delta 规则像用铅笔写字，写之前先擦掉同一位置的旧字；
- 门控像纸张本身的褪色速度，决定哪些内容会自然消失；
- KDA 的通道门控，则是让不同栏目用不同的墨水。

这和计算机的存储层级是同一个道理。CPU 有寄存器、L1/L2 缓存、内存、磁盘，每一层的容量和延迟差一个数量级，没有哪一层能通吃。大模型现在也在长出同样的结构：少数全注意力层当「工作内存」，大量线性层当「压缩后的长期记忆」，中间用 3:1 的比例做带宽分配。

所以「Transformer 要被取代了吗」这个问题，本身可能就问错了。2026 年发生的不是取代，是**分层**——注意力没有被扔掉，它只是从「唯一的记忆方式」退化成了「记忆层级里最贵的那一层」。

而 Delta Rule 提醒我们的是更朴素的一件事：一个好的记忆系统，关键不在于能存多少，而在于**知道什么时候该改**。这一点，从 1960 年的感知机到 2026 年的百万上下文模型，其实没变过。
