> 参考论文： [Image Generators are Generalist Vision Learners](https://arxiv.org/abs/2604.20329v1)  
> 项目主页： [Vision Banana](https://vision-banana.github.io/)

很多计算机视觉任务，过去都有自己的“专用模型”。

要做目标分割，可以使用 SAM；要做深度估计，可以使用 Depth Anything；要预测表面法线，又需要另一套模型。它们在训练目标、网络结构和输出格式上各不相同。

Vision Banana 提出了一个很大胆的反问：**既然图像生成模型已经学会了丰富的物体、纹理、空间和几何知识，能不能让它直接承担视觉理解任务？**

Google DeepMind 的论文《Image Generators are Generalist Vision Learners》给出了肯定答案：通过轻量级指令微调，图像生成器可以在保留图像生成能力的同时，统一完成二维和三维视觉理解任务。

本文不把论文当作“某个模型赢了几个 benchmark”的新闻，而是重点解释它背后的方法：为什么视觉理解可以被重新表述成图像生成，以及这种范式可能改变什么。

## 一、Vision Banana 到底是什么？

Vision Banana 建立在 Nano Banana Pro 之上。研究团队没有为分割、深度和法线分别设计多个任务头，而是对基础图像生成模型进行轻量级 instruction tuning：

```text
输入图像 + 任务指令
            ↓
      统一的图像生成器
            ↓
可解码的 RGB 视觉结果
```

例如：

- “分割图中所有汽车” → 生成一张颜色编码的分割图；
- “生成输入图像的深度图” → 生成一张可逆映射的深度可视化；
- “预测场景表面法线” → 生成 RGB 表面法线图。

关键点在于，模型的输出仍然是一张图像。不同任务的差异，主要通过指令和目标图像的编码方式表达，而不是通过更换模型结构表达。

## 二、核心思想：把视觉任务翻译成图像生成

传统视觉模型通常直接输出结构化结果：

```text
分割模型 → 每个像素的类别 ID
深度模型 → 每个像素的距离值
法线模型 → 每个像素的三维方向向量
```

而 Vision Banana 把这些结果统一编码成 RGB 图像。

这一步看似只是换一种输出格式，实际上非常关键。因为图像生成模型最擅长的就是生成像素空间中的视觉内容。只要目标结果能够被编码成“看起来像一张图”的形式，生成模型就可以使用自身已经学到的视觉先验来完成任务。

论文强调，这些可视化结果必须是 **可解码的**。也就是说，生成结果不能只是“看起来像深度图”，而需要通过明确的颜色映射还原出可以计算指标的深度数值、类别标签或法线向量。

## 三、三种任务如何编码？

### 1. 语义与实例分割

语义分割要求为每个像素分配类别，例如天空、道路、汽车和行人。最直接的做法是建立颜色到类别的映射：

```text
红色   → 汽车
绿色   → 行人
蓝色   → 道路
黄色   → 建筑
```

模型生成的不是一个整数矩阵，而是一张颜色图。评估时再把颜色反向映射成类别 ID。

实例分割更复杂，因为同一类别中的不同实例还要区分。例如两辆汽车不能使用同一种颜色。系统需要使用不同颜色表示不同实例，再通过像素聚类和映射恢复实例掩码。

这种做法的好处是统一，代价是颜色编码必须足够稳定，模型不能随意“创造一种近似颜色”，否则解码结果就会出错。

### 2. 单目度量深度

深度估计的目标是从一张普通图片推断场景中各点到相机的距离。

Vision Banana 使用颜色来表示深度。近处和远处对应不同颜色，评估时再通过逆映射恢复深度值。与只输出“相对远近”的深度图不同，论文关注的是 metric depth，也就是具有物理尺度意义的深度估计。

值得注意的是，项目页面强调 Vision Banana 在训练和推理时都不使用相机内参。论文还报告，深度任务使用了渲染引擎生成的合成数据，并排除了评测数据集中的真实训练数据。

### 3. 表面法线

表面法线是垂直于物体表面的三维方向向量，通常写成：

```text
n = (x, y, z), 其中 x、y、z ∈ [-1, 1]
```

RGB 的三个通道正好可以承担三个分量。通过把 `[-1, 1]` 映射到 `[0, 255]`，模型就可以生成一张法线 RGB 图，再将其反解为向量。

这是一种很漂亮的统一：

```text
类别 → 颜色
距离 → 颜色
方向 → RGB 三通道
```

视觉任务的结构化输出，被转化为图像生成器熟悉的像素输出。

## 四、它为什么可能有效？

### 图像生成本身需要理解世界

一个生成模型要生成合理的物体，不能只记住局部纹理。它至少需要在内部编码一些关于世界的知识：

- 物体通常是什么形状；
- 光照和阴影如何变化；
- 物体之间怎样遮挡；
- 近大远小如何形成；
- 物体表面具有什么几何结构；
- 什么样的布局看起来合理。

过去我们把“生成”和“理解”看成两条不同路线：生成模型负责画图，判别模型负责识别。但 Vision Banana 的结果暗示，生成预训练可能已经学习了相当丰富的视觉表示，只是过去没有被任务指令正确调用出来。

这和语言模型的发展有些相似。语言模型通过预测 token 学到语法、事实和一定的世界知识；图像生成模型也可能通过生成视觉内容学习物体、空间和几何规律。

### 指令微调负责打开能力

Vision Banana 的重点不是从头训练一个庞大的视觉基础模型，而是用较低比例的视觉任务数据进行 instruction tuning。

这意味着微调阶段更像是在告诉模型：

> 你已经拥有很多视觉知识，现在学会按照这个任务指令，把知识输出成可计算的视觉结果。

同时，训练数据中仍混合原有的图像生成数据，用来尽量保持基础模型的生成和编辑能力。

## 五、论文报告了什么结果？

论文在二维分割和三维理解任务上进行了评测。项目页面展示了包括 Cityscapes 语义分割、SA-Co/Gold 实例分割、RefCOCOg 指代表达分割和 ReasonSeg 推理分割等结果。

论文和项目页面报告的代表性结果包括：

- Cityscapes 语义分割 mIoU：Vision Banana 为 **69.9**；
- RefCOCOg val 指代表达分割 cIoU：Vision Banana 为 **73.8**；
- ReasonSeg val 推理分割 gIoU：Vision Banana 为 **79.3**；
- 六个基准上的平均单目度量深度 δ1：**0.882**；
- 在与 Depth Anything 3 同样评测的四个数据集上，平均 δ1 为 **0.929**，对方为 **0.918**；
- 四个数据集上的表面法线平均角度误差为 **18.928°**，对比 Lotus-2 为 **19.642°**。

这些数字需要谨慎解读：不同模型的训练数据、推理流程、提示词和评测设置可能不同，不能简单把所有结果理解成完全公平的“同条件单挑”。但它们仍然说明了一件重要的事：**一个以生成能力为核心的模型，可以在多个视觉理解任务上达到甚至超过专用模型的表现。**

在生成能力方面，论文也报告了与基础模型相近的结果：在 GenAI-Bench 文生图评测中，Vision Banana 相对 Nano Banana Pro 的胜率为 **53.5%**；在 ImgEdit 图像编辑评测中，Vision Banana 胜率为 **47.8%**，基础模型为 **52.2%**。这说明轻量微调并没有明显摧毁原有生成能力。

## 六、这不是“一个模型马上替代所有专用模型”

Vision Banana 的意义很大，但不应该被过度宣传成“专用模型已经没用了”。

第一，RGB 编码会引入新的误差来源。模型生成的颜色如果偏移，解码后的类别、深度或向量就会受影响。

第二，生成模型的输出具有一定随机性。对于需要像素级稳定、严格可复现的工业测量任务，输出一致性仍然非常重要。

第三，视觉任务的评价不只看平均指标。医疗、自动驾驶、机器人和测绘等场景还需要可靠性、校准、长尾数据表现和安全边界。

第四，论文中的零样本迁移结果很强，但结果依赖具体提示、输出编码和解码协议。实际应用时仍需要完整的工程管线，而不是简单调用一张图片接口。

因此，更合理的判断是：Vision Banana 展示了一条很有潜力的统一路线，而不是宣布所有视觉专用系统立即终结。

## 七、对计算机视觉的启发

### 1. 任务头可能不再是唯一选择

传统架构通常为每种任务设计专门输出头。Vision Banana 说明，任务头可以被“任务指令 + 统一输出空间”部分替代。

未来的视觉基础模型可能不再按“分割模型、深度模型、检测模型”划分，而是一个能够理解多种视觉指令、生成多种可解码结果的统一模型。

### 2. 图像生成预训练可能类似视觉领域的语言预训练

论文最有野心的观点是：生成式视觉预训练可能扮演类似 LLM 预训练的基础角色。

它的逻辑是：

```text
大规模图像生成训练
        ↓
学习物体、纹理、布局与几何先验
        ↓
轻量任务指令微调
        ↓
分割、深度、法线等通用视觉能力
```

如果这一趋势继续成立，视觉基础模型的竞争核心可能从“为单个任务设计更强的头”转向“谁拥有更强的生成式视觉先验”。

### 3. 输出空间设计本身成为模型设计的一部分

以前我们更关注网络结构和损失函数；Vision Banana 提醒我们，**如何表示任务结果**同样重要。

把一个数值场、类别图或向量场设计成可逆的图像表示，既利用了生成模型的原生能力，也为统一训练提供了接口。

这可能推广到更多任务：光流、3D布局、姿态、材质属性，甚至机器人动作规划，都可以尝试寻找适合生成模型的可解码视觉表示。

## 八、我的理解：视觉模型正在从“识别器”变成“可编程模拟器”

传统视觉模型像一组工具箱：检测是一把扳手，分割是一把螺丝刀，深度估计又是另一件工具。

Vision Banana 更像一个可编程的视觉系统。用户通过自然语言告诉它想观察什么、以什么形式输出，模型再生成一张符合协议的视觉结果。

当然，这个“模拟器”距离真正可靠的世界模型还有距离。它可能生成视觉上合理、但数值上错误的结果；也可能在训练分布之外出现不稳定行为。

但范式的变化已经很清楚：

```text
过去：为每种视觉任务训练一个模型
现在：用统一生成接口调用多种视觉能力
未来：视觉理解、生成和行动可能共享同一个世界表示
```

Vision Banana 最值得关注的地方，不只是它赢了哪些榜单，而是它重新定义了一个问题：**视觉理解是否一定要以分类、回归或掩码张量的形式存在？**

如果答案是否定的，那么生成模型就不只是“会画图的模型”，而可能成为一种通用的视觉学习器。

## 结语

Vision Banana 的核心贡献，可以用一句话概括：

> 通过把视觉任务统一编码为可解码的 RGB 图像生成，研究者用轻量级指令微调把图像生成器转化成了通用视觉学习器。

它展示了生成式预训练在视觉理解上的潜力，也提醒我们不要过早把模型能力限制在它的表面接口上。

未来的视觉基础模型，可能同时具备三种能力：

- 生成视觉世界；
- 解释视觉世界；
- 根据任务指令，把视觉世界转换成可计算的结构化结果。

真正值得追踪的，不是“Vision Banana 能不能取代某一个专用模型”，而是这种统一范式能否在更严格、更可靠、更开放的真实场景中继续成立。
