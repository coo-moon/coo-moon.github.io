## 背景：为什么自己做量化因子研究

我平时有一套实时盯盘体系（每天 14:30 推送持仓分析、支撑压力、板块联动），但那是"监控型"能力——回答的是"现在要不要动"。

缺的是"研究型"能力：**哪些量价因子真正有效？能不能用机器学习构建一个选股模型？** 于是决定在本地环境搭一条完整的"因子研究 + ML 选股"管线。

## 为什么不用现成的 Qlib

微软 Qlib 是 AI 量化领域公认的旗舰框架，Alpha158 因子体系也是它的核心资产。但两个现实问题：

1. **ARM64 无预编译包**：`pyqlib` 在 PyPI 上只有 x86_64 / macOS / Windows 的 wheel。`pyqlib<=0.9.5` 只有 cp37m/cp38 的 ABI，`pyqlib>=0.9.6` 没有 `linux-aarch64` 平台包，源码编译风险高（protobuf/cython 依赖链在 ARM 上容易踩坑）。
2. **官方数据源被墙**：Qlib 默认的 azure 数据下载在国内网络环境基本不可用。

结论：**框架的"因子体系 + 模型思路"是开源的，但数据管道可以完全自己搭**。用 Tushare（行情/复权/基本面）+ LightGBM 做一个等价实现，绕开编译地狱，而且每一步都可控、可解释。

## v1：先跑通最小闭环

第一版目标不是效果好，而是**验证管线正确**。最小配置：

- **股票池**：沪深300 成分，主板过滤（剔除 300/688/8 开头——个人没有创业板/科创板权限，贴近真实可交易范围）
- **数据**：Tushare `daily` + `adj_factor` 做后复权，2~3 年
- **因子**：Alpha158 核心子集 19 个（动量/乖离/波动/量能/区间位置/斜率）
- **模型**：LightGBM 回归，预测未来 5 日收益
- **评估**：严格 walk-forward

v1 结果（测试段）：**IC ≈ 0.013**，分层收益杂乱无章。这个结果在意料之中——股票池小、因子少、历史短。但**管线跑通了**，这是最值钱的一步：数据 → 因子 → 训练 → 评估 → 存模型的链路没有任何环节是黑盒。

## 贯穿始终的三条工程铁律

这三条决定了结果可不可信，比模型本身重要得多：

### 1. 严格 walk-forward，杜绝未来穿越

按**日期断点**切分：train 62% / valid 18% / test 20%。test 段是模型**从未见过**的最近 20% 数据。

```
train  <  62% 日期  <  valid  <  80% 日期  <  test
```

如果按行数随机切分，同一天的样本可能一半在训练集、一半在测试集——模型等于"提前看到答案"，回测指标全是幻觉。这是量化研究的第一原则。

### 2. 后复权

用 `close × adj_factor / 最新adj_factor` 构造后复权价，消除除权除息造成的价格跳变。不复权的话，一次 10 送 10 会让"收益"凭空多出 100%，因子和标签全部失真。

### 3. 数据末尾锚定

Tushare 的 `trade_cal` 是**未来日历**（包含未发生的日期），但 `daily` 实际数据只到某个真实日期。必须先用 `daily` 接口探测真实末尾再回推起点，否则区间会落在空白上，拉回一堆空数据。

## v2：放大数据 + 加入基本面

v1 证明管线正确后，v2 做四件事：**更大的股票池、更长的历史、更多的量价因子、基本面因子**。

| 维度 | v1 | v2 |
|---|---|---|
| 股票池 | 沪深300（251只主板） | 中证800（620只主板） |
| 历史 | 3 年 | 10 年 |
| 样本量 | 18 万 | **120 万** |
| 因子数 | 19（纯量价） | **37（量价28 + 基本面9）** |
| 测试段 IC | 0.013 | **0.078** |
| RankIC | -0.008 | **0.047** |
| 分层 Q1→Q5（未来5日） | 杂乱 | **0.18% → 1.24% 严格单调** |
| 多空 spread | 0.44% | **1.06%** |
| Top 层相对超额 | 0.40% | **0.70%** |

最有意思的变化：**基本面因子一进来就霸榜了**。测试段重要性前几名是 `pb_log`、`pe_ttm_log`、`log_mv`、`dv_ttm`、`turnover`——估值、市值、换手率这些"慢变量"对大盘股未来收益的区分度，明显强于纯量价。

### 基本面数据哪来的

Tushare `daily_basic` 接口直接给日频的估值/市值/换手：

```python
daily_basic: pe_ttm, pb, ps_ttm, dv_ttm, total_mv, circ_mv, turnover_rate
```

实测踩到一个权限坑：`fina_indicator`（ROE/ROA 等财报指标）和 `stk_holdernumber`（股东户数）在当前的 Tushare token 下**返回空**（这两个接口需要更高积分）。所以基本面只做到 `daily_basic` 这一层。想加 ROE/股东户数，要么换更高权限的 token，要么走 baostock。

### 因子清单

37 个因子，全部由 OHLCV + 基本面日频数据在组内（按股票）计算：

| 因子族 | 因子 |
|---|---|
| 动量 | ret_1 / ret_3 / ret_5 / ret_10 / ret_20 / ret_60 |
| 均线乖离 | ma_bias5 / 10 / 20 / 60（现价偏离均线幅度） |
| 波动 | std5 / 10 / 20 / 60（收益标准差） |
| 区间 | range5 / 10 / 20 / 60（区间振幅）、pos20 / pos60（区间位置）、hilo（当日振幅） |
| 量能 | vol_ratio（量/5日均量）、turn20（量/20日均量）、vol_trend（5日均量/20日均量） |
| 趋势斜率 | slope5 / slope20（对数价格线性回归斜率） |
| 摆动 | rsi14、stoch_k9、roc20 |
| 基本面 | pe_ttm_log、pb_log、ps_ttm_log、dv_ttm、log_mv、log_circ_mv、turnover、turn_bias |

**工程细节**：10 年 × 620 只 ≈ 120 万行的面板，任何逐行 Python 循环都是灾难。斜率因子用滑动窗口向量化，一步到位：

```python
slope = (Σ (j - k/2) · y) / (k(k² - 1)/12),  j = 0..k-1
```

等价于线性回归斜率，但用 `numpy.lib.stride_tricks.sliding_window_view` 一次算完，比 `rolling(x).apply(np.polyfit)` 快几个数量级。

## 系统性调参：一个反直觉的结论

用 Optuna 跑了 40 组超参搜索，目标函数是验证段 RankIC（在 walk-forward 切分下，用 train 训练、valid 选优、test 只做最终评估，调参本身也不允许碰 test）。

- 最优 valid RankIC：**0.0718**
- 落地超参：`n_estimators=570, lr=0.024, num_leaves=40, max_depth=11, subsample=0.67, colsample=0.83, min_child=140, reg_alpha=1.22, reg_lambda=6.18`
- 调参后的测试段：IC 0.0777 → **0.0792**，spread 1.06% → **1.10%**

**结论：默认参数已经接近最优，调参只带来约 2% 的提升。** 这次能力的决定性提升来自"更大的股票池 + 更长的历史 + 基本面因子"，而不是超参。这本身是个值得记住的经验：**模型的天花板由因子和数据决定，调参只是在逼近天花板**。

## 落地：每日盘前给自选池打分

研究模型的终点是服务日常决策。流程：

1. 训练好的模型持久化为 `alpha158_model_v2.pkl`（模型 + 因子顺序 + 超参）
2. 写一个 `daily_score.py`：每天对自选池（持仓 + 观察清单）每只标的算最新一天的 37 个因子 → 模型预测"未来 5 日上涨倾向" → 池内排百分位
3. 挂在 cron 上，工作日 09:15 自动推送到飞书（`no_agent` 模式，脚本直接输出，零 token 消耗）

实际输出长这样：

```
1. 🔺Top 半导体设备ETF(159516)  分100 · 现价0.723 · 近5日-7.4%
2. 🔺Top 生物医药ETF华安(159508) 分87.5 · 现价0.805 · 近5日-7.4%
...
8. 🔻 比亚迪(002594)  分12.5 · 现价90.66 · 近5日+0.9%
```

一个有意思的现象：v1 模型给"近期大跌 12.6% 的生益科技"打了 100 分（纯量价视角的"超跌反弹"），v2 加入基本面因子后它掉到 37 分——**估值/市值因子修正了纯量价的判断**。

## 踩坑清单（都是真金白银换的）

1. **Tushare `index_weight` 的 `con_code` 带后缀**（`600519.SH`），要先 `.split(".")[0]` 再补零。
2. **因子计算必须组内 `reset_index(drop=True)`**：`pd.Series(numpy数组)` 默认索引是 0..n-1，如果 DataFrame 用的是全局索引（merge 后常见），所有因子会对齐错位变成 NaN，面板只剩几百行——症状极其隐蔽。
3. **`daily_basic` 选列要在 `b["code"]=code` 之后做**，否则 `code` 不在接口原始列里，会被列过滤干掉，缓存缺主键。
4. **评估段遇到 `inf` 会让 corr 返回 NaN**：先 `np.isfinite` 掩码再算相关性；用 numpy 的 `np.corrcoef` 而不是 pandas Series.corr（MultiIndex 面板的索引对齐会报 `cannot join`）。
5. **缓存文件名别用代码列表拼**：用池名（如 `000906`）+ 样本数后缀，冒烟测试（`--limit 60`）和全量（`--limit 0`）的缓存分开，防止小样本污染大缓存。
6. **大面板禁止 `rolling(x).apply(函数)`**：120 万行用 apply 会跑哭，改成 `sliding_window_view` 向量化。
7. **权限探测先行**：动手写完整管线前，先花两分钟测一遍 token 对各接口的权限（ROE、股东户数这种高频刚需接口经常没权限），省得写完了才发现数据源不存在。

## 局限与下一步

诚实面对局限：

- **IC 0.079 依然是弱信号**。它意味着"每 5 日多空差 1.1%"，在真实交易中会被手续费、滑点、涨跌停和流动性吃掉不少。这东西的价值是**优化选股顺序、辅助决策**，不是印钞机。
- **ETF 没有基本面特征**：自选池里 ETF 占多数，模型以 NaN 处理它们，所以 ETF 的分数仅供参考。
- **测试段 IC 是"事后统计"**：模型表现会漂移，需要月度滚动再训练来保持新鲜度。
- **ROE/股东户数缺口**：等有更高权限的数据源可以补上。

值得做的下一步：

1. 换中证500/全A 股票池（中小盘的量价因子信号更强）
2. 扩到 Alpha158 全量 158 因子
3. 改用 rank objective 或排序损失，直接优化排序质量
4. 月度滚动再训练 + 记录每次的 IC 漂移

## 更新（2026-08-25）：四个"下一步"全部落地

上一节的四个方向，我全部做完了，这里记录结果：

### 1. 换中证500 股票池 → IC 更强

中小盘的量价信号确实更强，RankIC 从 0.047 提到 0.073：

| 指标 | 中证800 | 中证500 |
|---|---|---|
| 样本 | 120 万 | 72 万（333 只 × 10 年） |
| IC | 0.079 | **0.0869** |
| RankIC | 0.047 | **0.0732** |
| 分层 Q1→Q5 | 0.17→1.28% | **0.02→1.48%** |
| 多空 spread | 1.10% | **1.46%** |

### 2. 因子扩到 92 个（Alpha158 全覆盖）

37 → 92，补齐全部家族：K线比例、多周期动量 `ret_{2..50}`、乖离 `ma_bias_{30..240}`、RSV、量能 `vma/vstd/vroc`、**量价相关 `corr_cv`（直接进重要性前3）**、OBV 趋势、换手 `tma/tstd`。全部向量化计算（10 年 × 72 万行也能秒级构建）。

### 3. rank objective → 负结果，但很关键

全量对比 `lambdarank` vs 回归：**rank 的 IC 只有 0.009，而回归是 0.087**，分层也几乎失真。原因：`lambdarank` 优化的是 NDCG（位置加权）+ 5 档糙量化，与我们的评估口径（IC / 分层收益）不匹配。**结论：横截面选股这种场景，回归目标明显更优**——不是所有"更高级"的目标都更好，要用数据说话。

### 4. 月度滚动再训练 + IC 漂移 → 必须做

44 个月逐月真实预测（每月用最近 24 个月重训，预测当月）：

| 指标 | 值 |
|---|---|
| 平均 IC | **+0.096** |
| ICIR（IC均值/标准差） | 1.06 |
| IC>0 胜率 | **95%**（44 个月 42 个月为正） |
| 平均 RankIC | +0.080 |
| 平均 spread | +1.39% |
| 最近 6 月平均 IC | +0.056（**< 全期 +0.096，有衰减**） |

逐月时间表里能清楚看到 2024-10/11（IC≈0.22/0.20）、2025-04（0.30）等强月，也有 2025-12、2026-07 的负值月。**最近 6 个月 IC 低于全期均值，实证了不重训模型会逐渐钝化**——所以我把"每月 1 号自动重训并更新每日打分模型"设成了 cron，让模型永远新鲜。

## 更新（2026-08-26）：三次迭代把模型推向历史最强

v3 之后又做了三件事，让它从"能跑"走向"能避雷、更锋利"。

### ① 可交易性过滤——剔掉买不进的票

打分前剔除**一字涨停（买不进）、停牌、日成交额 <3000 万、股价<2 元、ST**。A500 主板 369 只筛后剩 364 可交易——**以前 Top 里偶会混进"看着分高其实买不到/不能买"的票，现在直接进不了候选**。（坑：Tushare `daily` 的成交额 `amount` 单位是**千元**，不是元，阈值按错会误杀全部。）

### ② 真实财务因子——模型从纯量价升级为"量价+基本面"

用 akshare 业绩报表（一次拉一个报告期全市场），聚合 2016Q1 以来的 **ROE / 净利同比 / 营收同比 / 毛利率 / 每股经营现金流 / EPS**，用"公告日期"精确 forward-fill（只取已披露报告期，防未来穿越）并入特征，因子 92→98。

效果立竿见影：**一只亏损 + 军采暂停的"硬伤股"从 Top3 被压出去**，roe / 毛利率 / 净利同比全部冲进模型重要性前 10——模型第一次能识别"基本面很差但最近跌得多"的坑（光看量价它是最佳超跌反弹标的）。

### ③ 多周期复合标签 + 行业中性化——最大的一跳

- **多周期复合标签**：把"只预测未来 5 日收益"升级成"5 日 + 10 日加权复合"（`fwd_ret = 0.5·Δ5日 + 0.5·Δ10日`）。测试段指标大幅跃升：

| 指标 | 单周期5日 | 多周期复合5&10 |
|---|---|---|
| IC | 0.0814 | **0.0944** |
| RankIC | 0.0727 | **0.0993** |
| 多空 spread | 1.41% | **1.94%** |
| 分层 Q5 | 1.42% | **1.99%** |

  而且财务因子依然全在重要性前 9——**多周期标签和财务因子是互相增益，不是二选一**。
- **行业中性化**：打分时对每只做 `score − 行业均值`（行业内相对强弱），Top3 现在是跨行业分散，避免单个板块整体霸榜。

### 当前模型

中证500 · **98 因子（量价+财务）** · **多周期复合标签** · 调参后超参，test 段 **IC 0.0944 / RankIC 0.0993 / spread 1.94% / 分层单调到 Q5 1.99%** —— 到目前为止最强的一版。

## 小结

这条管线从 v1 到 v2、再到 v3 的核心经验，浓缩成三句话：

1. **先跑通最小闭环，再放大**——管线的可信度（尤其是防未来穿越）比任何单点技巧都重要；
2. **能力的提升主要来自数据和因子，不是调参**（Optuna 调参只提升约 2%）；伪高级的目标（lambdarank）在此场景反而更差，一切以测试段指标为准；
3. **量化研究的第一原则是诚实**——报告测试段（模型没见过的数据）的指标，别拿训练集自嗨；并且要监控 IC 漂移、定期重训。

全部代码和数据管道都固化在本地脚本 + skill 里，每天盘前自动给自选池打分，每月自动重训。
